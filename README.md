[Repository](https://github.com/JeongUk00/book-management-frontend.git) · `React 19` `Vite` `react-router-dom` `json-server` `OpenAI API` `GPT Image 2`

| 항목 | 내용 |
|:---|:---|
| 기간 | 2026.05.22 ~ 2026.05.27 |
| 역할 | 프론트엔드 구현, 도서 CRUD 흐름 설계, AI 표지 생성 기능 연동 |
| 문제 정의 | 도서 내용은 텍스트로 정리되지만, 표지는 직접 만들기 어렵고 관리 화면과 생성 기능이 분리되면 사용성이 떨어진다고 봤습니다. |

<details>
<summary>프로젝트에서 신경 쓴 부분</summary>

- 도서 목록에서는 검색어와 선택 상태를 분리해서 관리하고, 현재 검색 결과 기준으로 전체 선택/해제가 되도록 구현했습니다.
- `BookForm`을 등록/수정 페이지에서 함께 쓰도록 만들어 같은 입력 검증 로직을 재사용했습니다.
- AI 표지 생성은 품질, 크기, 포맷, 추가 요청사항을 사용자가 직접 조절할 수 있게 했습니다.
- API Key는 코드에 하드코딩하지 않고 입력값 또는 `.env.local`을 통해 사용할 수 있도록 구성했습니다.
- 이미지 생성 중 페이지 이동이나 삭제를 할 때 작업이 끊길 수 있다는 점을 사용자에게 확인하도록 처리했습니다.

**배운 점**

처음에는 CRUD만 잘 되면 된다고 생각했는데, 막상 AI 표지 생성 기능을 붙이니 화면 흐름이 훨씬 중요해졌습니다. 생성 중 상태, 미리보기, 저장 후 즉시 반영, 실패 메시지까지 이어져야 사용자가 기능을 믿고 쓸 수 있었습니다. 단순히 API를 호출하는 것과 서비스 안에 자연스럽게 넣는 것은 꽤 다르다는 걸 느꼈습니다.

### Product Review Analyzer

> 고객 리뷰를 분석, 요약하고 비즈니스 인사이트까지 제안하는 다중 Agent 파이프라인

[Repository](https://github.com/JeongUk00/Product-Review-Analyzer) · `Python` `LangGraph` `LangSmith` `GPT-4o-mini` `Streamlit` `ChromaDB` `HITL`

| 항목 | 내용 |
|:---|:---|
| 기간 | 2026.05.11 ~ 2026.05.14 |
| 역할 | 조장, Agent 흐름 설계, 결과 정리 및 발표 방향 관리 |
| 문제 정의 | 리뷰 수가 많아질수록 사람이 직접 읽고 분류하는 방식은 시간과 비용이 커지고, 어떤 단계에서 오류가 났는지도 추적하기 어렵습니다. |
| 해결 과정 | 리뷰 수집부터 감성 분석, 요약, 인사이트 도출까지 Agent를 나누고 LangSmith로 실행 흐름을 추적했습니다. 판단이 애매한 부분은 HITL 구조로 사람이 개입할 수 있게 설계했습니다. |
| 결과 | 리뷰 400건 기준 수동 처리 26~33시간 수준의 작업을 약 13분으로 줄였고, 비용도 약 99.8% 절감하는 구조를 만들었습니다. |

**배운 점**

Agent는 여러 개를 붙인다고 좋아지는 게 아니라, 각 Agent의 책임과 실패 지점을 분명히 잡아야 안정적으로 돌아간다는 걸 배웠습니다. 특히 LangSmith로 중간 과정을 보면서, 기록이 남아야 개선도 가능하다는 걸 체감했습니다.

**배운 점**

### Airline Customer Satisfaction Prediction

> 항공사 고객 데이터를 활용한 만족도 예측 모델링 프로젝트

[Repository](https://github.com/JeongUk00/airline-customer-satisfaction-prediction) · `Python` `XGBoost` `DNN` `EDA` `Class Weight` `Oversampling`

| 항목 | 내용 |
|:---|:---|
| 기간 | 2026.04.14 ~ 2026.04.20 |
| 역할 | 서기, 코드 정리, 모델 실험 결과 정리 |
| 문제 정의 | 데이터의 약 90%가 만족 클래스로 치우쳐 있어 Accuracy만 보면 모델이 좋아 보이지만, 실제로는 불만족 고객을 놓칠 수 있었습니다. |
| 해결 과정 | 클래스 불균형을 확인하고 Class Weight와 Oversampling을 비교했습니다. 단순 정확도보다 Macro F1-score와 소수 클래스 지표를 중심으로 모델을 평가했습니다. |
| 결과 | Macro F1-score 0.93, class 0 Precision 0.77에서 0.95로 개선된 DNN 모델을 도출했습니다. |

**배운 점**

처음 Accuracy 0.97을 보고 좋아했는데, 알고 보니 모델이 거의 다 '만족'으로 예측하고 있었습니다. 이 경험 덕분에 좋은 숫자를 보는 것보다, 문제에 맞는 숫자를 고르는 게 먼저라는 걸 배웠습니다.
